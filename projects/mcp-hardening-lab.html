01. why it matters

AI agents now call tools through MCP servers: read a repo, call a cloud API. Operators trust two things: that a "read-only" tool only reads, and that a deny list actually denies. Both advisories broke one of those assumptions. The lab shows how, and what a fix that holds looks like.

02. lab 01: when git status runs code

The bug. The Git tool runs inside whatever repository the client points it at. That repository's own .git/config can name a program, and Git runs it on ordinary commands:

config keytriggered bywhat Git does
core.fsmonitorgit statusruns the named program to list changed files
diff.externalgit diffhands the diff to the named program
filter.<x>.cleangit diff on the work treepipes file content through the named program

The scenario. An agent is asked to look at an unpacked archive or a copied folder. It calls git_status. The repo's config names a script, and the script runs with the MCP server's environment, including any tokens it was given. Nothing in the tool name said "execute".

# vulnerable.py
subprocess.run(["git", "-C", repo_path, "-c", "core.quotepath=false", *args])

# fixed.py
MIN_GIT = (2, 31)
HARDENED_CONFIG = (("core.fsmonitor", "false"), ("core.hooksPath", os.devnull),
                   ("core.pager", "cat"), ("submodule.recurse", "false"), ...)
DIFF_FLAGS = ("--no-ext-diff", "--no-textconv")
SUBMODULE_FLAG = "--ignore-submodules=dirty"

The fix.

  • Every Git call gets GIT_CONFIG_COUNT overrides, which outrank .git/config: core.fsmonitor=false, hooks path on the null device, core.pager=cat, signing and submodule recursion off.
  • Filter, merge and branch.*.mergeOptions drivers defined by the repo (scope local or worktree) are blanked. Global and system drivers such as Git LFS stay.
  • Diffs run with --no-ext-diff --no-textconv; status and diff with --ignore-submodules=dirty.
  • The tool refuses Git older than 2.31 (it ignores the overrides) and checks that the override really applied before running anything.

03. lab 02: a deny list that does not deny

The bug. The operator writes deny entries in CLI form, like iam create-saml-provider. The server turns the requested name into kebab case by putting a hyphen before every capital, so CreateSAMLProvider becomes create-s-a-m-l-provider. The strings never match, so the call is allowed. Names with consecutive capitals (SAML, MFA, DB, SSH) all fall through; TerminateInstances does not, which is why a test with only simple names stays green.

# vulnerable
re.sub(r"([A-Z])", r"-\1", op).lower().lstrip("-")

# fixed: same function for policy AND request
def canonical_token(operation):
    return re.sub(r"[^a-z0-9]", "", operation.lower())

The fix. One resolve function strips separators and case, then looks the name up in a small service model. Policy entries and requests both go through it, so the three spellings are the same operation. It fails closed: an unknown name is denied, a policy entry that does not resolve is a startup error, elicit never runs without a human confirmation, and the decision is applied at the call itself.

The last two rows are controls: the vulnerable build does read the policy, and the fix does not block legitimate calls.

05. operator checklist

Excerpt from CHECKLIST.md.

  • Override command-bearing Git config on every call, and confirm the override applied before running.
  • Refuse Git < 2.31: a warning is not a fix.
  • A read-only tool name is not a sandbox. Do not hand secrets to a Git server that can be pointed at a repo you did not create.
  • Confine the server to an allowlisted root, and still treat nested checkouts, archives and copied folders as untrusted.
  • Normalize policy and request with the same function, and test with names like SAML, MFA, DB, SSH.
  • Fail closed: unknown names denied, unresolvable policy entries stop startup, no policy data means no calls.

06. limits

  • Simplified re-implementations that show the bug class and the fix, not drop-in copies of the upstream servers.
  • Lab 01 does not jail repo_path to a root; that is an operator control listed in the checklist.
  • Lab 01 reads config one entry per line, so a driver value containing a newline is out of scope (upstream uses a NUL-delimited listing).
  • Lab 02's fail-closed default is stricter than the patched upstream, which still allows a call when no list matches.

07. safe by design

localonly
nonetwork
noreal cloud

The payload writes one marker file under /tmp and nothing else: no shell, no network, no credentials. The cloud is a dictionary in memory. Run it only on a machine you control, against repos you created for the lab.
